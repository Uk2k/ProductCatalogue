# Create and Read Products Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a testable Product vertical slice with `POST /products`, `GET /products`, and `GET /products/{id}`.

**Architecture:** Keep each use case in `Features/Products` with MediatR requests, handlers, validators, and endpoint mappings. The HTTP integration tests will host the real minimal API with `WebApplicationFactory<Program>`, override the SQL Server connection to a disposable Testcontainers database, and verify behavior through HTTP.

**Tech Stack:** .NET 8, minimal APIs, MediatR, FluentValidation, EF Core SQL Server, xUnit, WebApplicationFactory, Testcontainers.MsSql.

**Spec:** `docs/superpowers/specs/2026-09-10-create-product-design.md`

## Global Constraints

- Use vertical slicing under `src/ProductCatalogue.Api/Features/Products`.
- Use MediatR for commands and queries.
- Use GUIDs generated by the server for new Product IDs.
- Use `POST` for creation and reserve PUT/PATCH decisions for a later slice.
- Return `ProblemDetails` for validation failures.
- Use the existing Testcontainers SQL Server fixture; never depend on a developer-local database.
- Preserve the existing persistence migration and persistence tests.
- Do not add pagination, filtering, repository abstractions, global exception middleware, or OpenTelemetry in this slice.
